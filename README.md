# metatool

Inspect and clean metadata in `.docx` and `.pdf` files.

One script, two modes:

- `check` — flags metadata that suggests a document was generated by a script
  instead of typed manually.
- `clean` — strips or rewrites that metadata.

If no path is given, both scan a `files/` folder next to the script.

## Setup

```bash
pip install pikepdf --break-system-packages
```

(`python-docx` is not required — the script reads/writes the underlying XML directly.)

Optional TUI (`python3 metatool.py` with no subcommand):

```bash
pip install --user --break-system-packages textual
```

## Usage

```bash
# interactive
python3 metatool.py

# scan everything in ./files/ (default)
python3 metatool.py check

# scan specific files / a folder
python3 metatool.py check report.docx report.pdf
python3 metatool.py check submissions/

# machine-readable output
python3 metatool.py check --json report.docx > report.json

# clean everything in ./files/ (default), writes results/ under it with same names;
# name collisions get (1), (2), ... appended
python3 metatool.py clean

# clean a folder, write results elsewhere
python3 metatool.py clean --out-dir cleaned/ submissions/

# set an author name instead of a generic one
python3 metatool.py clean --set-author "Jane Doe" report.docx
```

## What check looks for

**docx** (`docProps/core.xml`, `docProps/app.xml`):

- `creator` / `description` referencing a known generation tool
- `created` date matching python-docx's default template timestamp (`2013-12-23T23:15:00Z`)
- `creator` differing from `lastModifiedBy`
- low `revision` count / `TotalTime` relative to page count

**pdf** (document info dictionary + XMP metadata stream):

- `Author` / `Creator` / `Producer` / XMP fields referencing a known generation tool
- `Author` being a library name while `Creator` is an office app
- `CreationDate` exactly equal to `ModDate`

### Flag levels

| Level | Meaning |
| ------- | --------- |
| `HIGH` | Strong, fairly direct evidence of programmatic generation |
| `MED` | Suggestive but not conclusive on its own |
| `LOW` | Common metadata pattern, worth noting but often benign |
| `WARN` | Expected metadata is missing entirely |

Findings are heuristics, not proof — always read them alongside the actual content.

## What clean does

**docx**: rewrites `docProps/core.xml` from scratch (creator, description, lastModifiedBy set
to the chosen author, random plausible revision/created/modified), strips `Manager`, `Company`,
`Template`, and `TotalTime` from `docProps/app.xml`, and drops `docProps/custom.xml` if present.

**pdf**: deletes every key in the document info dictionary and removes the XMP metadata stream
entirely; optionally re-adds `Author` if `--set-author` is passed.

Cleaned files go to a `results/` folder next to the source (or `--out-dir`), keeping the same
filename; if that name already exists there, `(1)`, `(2)`, ... is appended before the extension.

## Limitations

- Only cleans/checks file-level metadata (document properties). It does not touch document
  content, embedded revision history inside the body text, or hidden tracked changes.
- Cleaning metadata does not change how or by whom the content was actually produced — it only
  removes the properties that happen to reveal it.
- The tool list (`SUSPICIOUS_CREATOR_TOOLS` in `metatool.py`) is not exhaustive; add to it as
  needed for your use case.
